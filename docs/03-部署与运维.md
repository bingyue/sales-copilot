# 集智销伴部署与运维

## 首次部署

1. 准备 Linux 主机、Docker/Compose；构建机器使用 JDK 17/21、Maven、Node.js 22。
2. 获取项目，运行 `python3 scripts/init-env.py`，在目标部署目录生成独立账号与密钥。
3. 编辑 `deploy/.env` 的模型、PUBLIC_URL、HTTP_PORT；填写实际产品资料到 `deploy/products.json`。
4. `bash scripts/build.sh` 运行测试并生成 JAR 与 Web dist。
5. `bash scripts/start.sh` 启动数据服务、执行增量表结构、构建并启动 API/Web。
6. 确认 `/api/health` 返回 ready，再验证 `/tools/login` 和真实登录后的销售工作台。

初次数据库仅导入纯表结构，不导入上游演示客户、企业配置或密钥。SQL 使用 CREATE TABLE IF NOT EXISTS；已有源雀数据库迁移须先备份并核对版本，不能把旧库凭证直接提交到仓库。

当前 Compose 为单企业独立部署，数据位于命名卷。首次失败后再次启动会补齐缺少的表，不能仅依据 MySQL ping 判断业务表已完整创建。

## 腾讯云接入现有域名

优先使用现有 HTTPS 入口，将一个专用域名反向代理到 `127.0.0.1:HTTP_PORT`。配置 PUBLIC_URL 为该域名根地址。不要改写其他应用的站点或占用它们正在使用的端口。

Nginx 反向代理示例（放入目标域名现有 TLS server 中）：

```nginx
location / {
    proxy_pass http://127.0.0.1:8088;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 120s;
}
```

没有域名时可以显式配置 BIND_ADDRESS 和对应端口，通过主机公网地址验收；对外运营时使用已配置的 HTTPS 域名入口。数据库和 Redis 不发布公网端口。

登录地址是 `https://你的域名/tools/login`，账号密码在服务器私有 `deploy/.env`。切勿使用开发验收密码部署生产实例。

### 与现有网站共用 HTTPS

已有网站使用 `/api` 时，可把销伴部署在独立路径，避免覆盖其接口。在 `frontEnd/pc` 执行 `SALES_PUBLIC_PATH=/sales-copilot npm run build-check`，并设置 `PUBLIC_URL=https://你的域名/sales-copilot`。默认构建仍使用 `/tools/` 和 `/api`。

在现有 HTTPS server 中新增以下位置；应用容器仍绑定 `127.0.0.1:8088`，不开放数据库或新增公网端口：

```nginx
location = /sales-copilot { return 308 /sales-copilot/tools/login; }
location = /sales-copilot/ { return 302 /sales-copilot/tools/login; }
location ^~ /sales-copilot/ {
    proxy_pass http://127.0.0.1:8088/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 120s;
    proxy_buffering off;
}
```

保存原站点配置后先运行 `nginx -t`，通过才 reload。登录路径为 `/sales-copilot/tools/login`；回调路径为 `/sales-copilot/api/iycallback/handle`。登录 Cookie 使用独立名称与应用路径，避免与同站点应用混用。

## 更新与回退

- 发布前备份数据库和 uploads 卷，保存当前镜像 ID、Git commit 与部署配置副本。
- 新版本先运行测试与构建，再执行 start.sh。数据库脚本应继续采用增量方式；已有列变更应增加独立迁移文件。
- 如果新版本不能通过 health/登录验收，恢复旧 API 镜像和旧 dist，保留数据库与上传卷。
- 不使用 `down -v` 进行版本回退；该命令会删除业务数据卷。
- 产品目录修改后需重启 API，既有 AI 建议应重新生成以使用新目录。

## 运维检查

```bash
# 如没有 docker compose 插件，可将命令替换为 docker-compose。
docker compose --env-file deploy/.env -f deploy/compose.yaml ps
docker compose --env-file deploy/.env -f deploy/compose.yaml logs --tail=100 api
curl --fail http://127.0.0.1:8088/api/health
```

会话同步检查 `iyque_sales_sync_cursor` 的 sequence、last_attempt、last_error。读取失败时检查点不推进；修复配置/解密条件后会重试。未启用存档时，保持手工录入路径即可。

AI 失败只保存失败状态，不修改客户档案、跟进和实收。没有有效产品配置时，应补齐目录后再做产品推荐。当前部署不会自动发送销售助手生成的客户回复。

## 验收数据

`scripts/smoke-sales.py` 只用于独立测试环境。它创建测试档案和跟进，登记小额测试实收后作废，验证收入恢复。正式数据库不自动导入这些验收客户。

实际企微会话权限、第三方模型可用性及外部域名依赖部署时提供的配置；系统页面加载成功不代表这些外部集成已经配置完成。
